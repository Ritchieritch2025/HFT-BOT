# 标准指标战役 v1(可复用指令——每次迭代原样执行,输出同构表)

> 用法:对 agent 说"跑指标战役 v1,窗口=<日期范围>,对象=<影子版本/回放臂/实盘>"。
> 所有表编号固定(T0–T7),每次输出格式相同,直接和上一轮 diff。
> 修改本文件即升版本号,旧版本结果不得与新版本混比。

## 全局纪律(违反任一条,整轮作废)
- 只报数字表,禁止形容词;每个数字附样本量 n 和数据日期范围。
- 所有阈值/百分位按既定口径:tte 分层 + 时段日历化,对照尾 24h 分布。
- 回执含:代码 SHA、数据源清单、封存状态;基线门 SHA 必须与在跑代码一致。
- 按天切分报告(汇总表 + 逐日方差),单日样本 <30 的格子标灰。
- 结果三件套永远同报:**markout、成交率、净利润**——缺一即作废(防过度防御假冠军)。

## T0 武器射程(延迟 census)
| 指标 | 定义 | 过关线 |
|---|---|---|
| 撤单 RTT | 持久连接签名 DELETE,n≥25,p50/p95 | p95 ≤ 10ms |
| 冷连接首发 | 新 TLS 首请求 | 仅记录(保温强制后不应出现) |
| 锚信号到达 | Binance tick→进程内收到,p50/p90/p99,**必须含爆发时段** | p99 膨胀>3× p50 时 census 不过关 |
| 端到端 | tick 收到→判断→撤单 ACK,进程内打点(非录制口径) | 全链 p95 ≤ 100ms 且逐跳可审计 |

## T1 周期经济学(全样本)
赢/输/合计三行:n、占比、均值¢、中位数¢。口径=完整周期盈亏(配对锁差−退出成本−费用)。

## T2 孤腿损失分布(验收基准)
p50/p75/p90/p95/max + 孤腿总损/配对毛利比。
**验收红线(写死):VALIDATE 段 孤腿总损 ≤ 毛利 35% 且 p95 ≥ −10¢。**

## T3 撤单竞赛被打率
撤单意图后 200ms/1000ms 内被成交的笔数、占全部成交比例;与孤腿事件的重合数。
目标趋势:快锚盾上线后此表应显著下降——它是盾的直接疗效指标。

## T4 markout 战役
5s/30s/120s × 方向 × 价区(YES 等价 5 桶)× 便宜/贵侧。均值、中位、负占比。
验收参照:上一轮同表逐格 diff,恶化格子必须给解释或立案。

## T5 成交率与吞吐
每小时:报价时长占比、成交笔数、配对周期数、每周期等待时长中位。
与 T4 连读:markout 改善但 T5 塌方 = 过度防御,判负。

## T6 锚健康
β_1s/β_3s 当日漂移范围、basis EWMA ± σ_basis、锚 DISTRUST/DOWN 触发次数与时长、
staleness p95。β 单日漂移 >30% 时 B 段(锚进定价)自动冻结。

## T7 数据与运维预检(跑任何上表之前)
封存状态(昨日 SEALED?)、抽检(随机 2 系列×2 小时 trade_id 集合 vs API)、
磁盘水位+稳态增速(GB/h 实测,余量 <48h 即红)、录制三流心跳、
deadman 状态、GATE HOLD 未决清单。**T7 不绿,其余表不跑。**

## 输出与归档
- 单文件 `metrics/battery/<date>_<object>_v1.json` + 人读 markdown 摘要(只有表)。
- 每次跑完追加一行到 `metrics/battery/index.csv`:日期、对象、SHA、T2 是否达标、
  T0 端到端 p95、T1 均值——趋势线就是系统迭代的心电图。
- 与上一轮的 diff 表(哪些格子变好/变坏)自动生成,人工只看 diff。

## 点火联锁(金丝雀/放量前置条件,全绿才许动钱)
T0 端到端过关 + T2 达标(VALIDATE 段)+ T7 全绿 + deadman 落地。
任何一项转红,已运行实盘降级为只撤单模式。
