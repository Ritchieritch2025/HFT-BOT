## 阶段与闸门

### P0 — 口径冻结(0.5 天,纯文档+测试样例)

产出 `docs/C1_SPEC.md`,把下面每一条写成公式 + 3 个手算验收样例:

- 事件定义:顶档深度被吃 ≥50% = 「深度蒸发」;horizon 网格 {100ms, 200ms,
  500ms, 1s};回补 = 显示深度恢复 ≥80%(同侧同价带)。与 D3 口径逐字对齐,
  不许悄悄漂移(snapshot 不算回补证据、TTL 截尾语义照抄 limitations)。
- 分层:价位带(含 deep02 点名的 88-93¢ 拉锯带)× 运动组(MLB/网球/UFC…)
  × pre-game/in-play。
- 阈值 T:不拍脑袋,P3 里对 T ∈ {40%, 50%, 60%, 70%}@1s 全扫。
- **闸门 G0**:SPEC 冻结 + 验收样例过,才准写代码。

### P1 — L2 采集硬化 + 逐日封存(关键路径,日历时间 ~3-4 周)

现状是硬伤:8 天里只有 3 天干净(07-13 一个 seq gap 就 REFUSED;07-14
parse_errors 2.7 万 + 帧丢失 = 灾难)。20 天闸门要的是 **20 个 L2 干净日**,
按现在的合格率(3/6 有采集日)要等太久,必须先修采集,不是先写策略。

- 采集器跑在 **EC2 生产机**(6ms 到交易所;Mac 34ms 只做备援副本)。
- 修的就是已知死因:重连后 snapshot 重基线逻辑、error-25 过载分片预案
  (协议文档里留了 seam)、录制器丢帧(先查 07-14 的 recorder_marker:loss)。
- 观察名单:MLB 全部当日场次 + deep02 88-93¢ 候选市场 + 每天固定 3 个
  对照组(网球/UFC/宽基各 1)。名单每天开盘前自动生成,记进当日收据。
- 每日自动化:采集 → 质量审计(复用 D3 审计,标准不放松)→ 封存 + 收据
  → 失败当天在 dashboard 报红(接"报表红绿灯"习惯)。
- **闸门 G1**:连续 7 天合格率 ≥ 6/7 才算硬化完成;然后攒到
  **≥20 个干净封存日**(与已有 07-12/15/17 合并计数)。

### P2 — 队列位置模拟器 queue_sim(核心新造件,~3 天,可与 P1 并行)

把「显示深度回补」换算成「我的单成交没有」的那台机器:

- 输入:封存 L2 日(snapshot + delta 流)。在指定价位注入一张虚拟单,
  按价格-时间优先维护它前面的排队量:前方量随该价位成交递减、随撤单递减。
- **诚实的硬点:delta 流看不出撤单撤的是队首还是队尾。** 所以不出点估计,
  出上下界:悲观假设(撤单全在我后面 = 前方量只靠成交消化)与乐观假设
  (撤单全在我前面)各算一遍。**上闸门的一律用悲观值。**
- 输出(逐格:价位带 × horizon × 日):虚拟单成交率、到手时间分布、
  成交瞬间的对手方向。
- 验收:合成序列单元测试(手算 10 例)+ 与 C++ OrderBook 不变量交叉核对
  + 同一日重放两遍结果逐字节一致。
- **闸门 G2**:悲观成交率在 3 个已有干净日上符号方向稳定(不是数值相等),
  且乐观/悲观带宽窄到有决策意义(带宽比 < 3×;否则说明撤单歧义吞掉了
  信息,C1 直接降级为"仅退出信号",不做进攻)。

### P3 — C1 影子回放:规则 + 分账(~2 天,依赖 P2;先在 3 个干净日试跑,20 日到齐后重跑定案)

- 规则实现(纯离线):在 (价位带 × T) 格子里,回补风险率 > T 时双边挂
  虚拟单;被吃后按 SPEC 决定 跟随回补 / 等待 / 撤退。
- 成交用 queue_sim 悲观口径;费用用 C++ cost model 口径;体育 maker 费按
  现行费表。
- **分账是本阶段的灵魂**,一张表两列:
  - 回补场合(事后 1s 内深度恢复):赚的价差;
  - 不回补场合:挨的打(逆向选择成本)。
  外加第三列:VPIN>0.9 / 日程 T−30min 门开着时被闸掉的那些格子的假想损益
  (证明防御闸真的在省钱)。
- 参数扫描:T × 价位带 × 单量,输出全格净¢/合约 + n + t 检验
  (**格子 n ≫ 10k 才许信** — VAR sketch 的教训直接继承)。
- **闸门 G3(TRAIN→VALIDATION 复用 D3 三闸漏斗)**:20 日到齐后,前段定参、
  后段(未见过的日子)重考;悲观口径下存在格子 净 ≥ +2¢/合约 且
  分账为「价差收入 > 被碾损失」。不过 = C1 处决,只保留其退出信号价值。

### P4 — live 影子(≥5 天,依赖 G3;宿主 = ws_shadow 扩展)

- 在 EC2 上对真实 WS 流实时跑 C1 决策 + queue_sim 虚拟单(仍然零写入、
  fail-closed 原样继承)。
- 量三件事:端到端决策延迟(事件→假想下单,p99 必须 < 20ms,给 100ms
  窗口留 5× 余量)、live 虚拟成交率 vs 回放预测的偏差(<30% 才算模拟器
  可信)、逐日净损益符号。
- **闸门 G4**:≥5 天、累计为正、无质量事故、延迟达标。

### P5 — 微实盘(依赖 G4 + WO-B 风控/killswitch + WO-C 下单器)

- maker 挂单被 intake 阶梯明文卡在 WO-B/WO-C 后面,本计划不越权。
- 首发:MLB 单一市场、单侧起步(先只挂我们有税收方向优势的 NO 侧,
  双边等单侧账本干净再开)、≤$200 抵押、kill-file 照微实盘四件套。

## 风险与止损点(建之前先认账)

1. **撤单歧义可能吞掉一切**:若 G2 带宽比 > 3×,C1 进攻性做市不成立,
   降级为 S1 的退出增强信号(深度不回补 = 提前撤)。这不算失败,算便宜的答案。
2. **观察名单偏置**:D3 自己声明 TARGETED_WATCHLIST ≠ 全市场;结论只许
   声称到名单内,不许外推。
3. **日历风险**:MLB 赛季 9 月底收;20 干净日 + P3/P4 全链约 5-6 周,
   没有留给返工的余量——所以 P1 合格率闸门是硬的,采集不稳就先别往下走。
4. **存储**:~25M 行/采集日,20 日 ≈ 5 亿行;EC2 磁盘按 zstd 归档层
   (三层仓库口径)预留,P1 第一天就核对水位,别重演磁盘扩容事故。
