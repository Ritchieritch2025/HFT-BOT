# W-LAT-BENCH-01 — 挂单/撤单延迟基准测试计划

**Status: PROPOSED — 待操作员批准后由工程 session 执行。**
**发起:**操作员要求(2026-07-16),背景 = deep02 信号地图指向做市策略,
防守速度(tick-to-cancel)是生死线。
**已有底子:**`work/latency_baseline/samples.ndjson`(2077 条,07-09 起):
Mac→Kalshi REST 热 RTT p50≈31ms、p99≈37ms、冷连接≈100ms。仅网络层。

## 延迟的解剖(要测的是整条链,不只是网络)

```
行情事件到达(WS) → 决策(引擎) → 构造+签名(RSA) → 发送 → 交易所处理 → ACK 返回
         └────────────────── tick-to-cancel 总延迟 ──────────────────┘
```

## 分层方案(按风险从零到有,逐层解锁)

### Tier 1 — 引擎内部计时(零风险,立刻可做)
- 测本地纯软件路径:决策循环耗时、订单构造、**RSA 签名耗时**
  (Kalshi 每个请求都要签名,未优化的 RSA-PSS 可达毫秒级,常被忽视)、
  序列化。基准:各环节 p50/p99,n≥10,000 次。
- 工具:C++ 基准挂进 `make check` 体系;结果落
  `work/latency_baseline/engine_bench.ndjson`。

### Tier 2 修订(操作员裁决 2026-07-16:demo 环境质量差,降级处理)

demo 撮合迟钝、盘口空洞,数字无参考价值。Tier 2 改为两件事:
- **Tier 2a — 生产只读延迟(真实的路,零风险):**对生产环境的
  只读 GET 端点(exchange/status、市场查询等,带鉴权)测完整往返:
  网络 + TLS + 鉴权 + 服务端处理。n≥1,000、跨时段。这就是"到真交易所
  柜台问一句话"的实测时间,是挂单/撤单延迟的主要成分(传输+鉴权)。
- **Tier 2b — demo 仅做软件路径验证(可选):**只验证我们的下单/撤单
  客户端代码"能正确走完一个回合",不采集任何延迟数字。懒 demo 验证
  正确性够用,验证速度免谈。
- **缺口如实记账:**交易所"下单处理耗时"这一段在 Tier 4(生产微基准,
  操作员另批)之前无法实测。backtest_latency.yaml 中该参数标注
  `UNMEASURED_CONSERVATIVE`,取 Tier 2a 实测 p99 再加保守余量,
  数字来源与假设写明,Tier 4 实测后替换。

### ~~Tier 2 — Demo 环境全链路~~(原文作废,见上)
- 环境:`external-api.demo.kalshi.co`(config/kalshi_facts.yaml 已验证可达)。
- 测:place→ACK、cancel→ACK、place+immediate-cancel 全回合;
  WS 行情事件→撤单 ACK 的端到端 tick-to-cancel 排练。
- 样本:n≥1,000,跨 ≥3 个时段(含 UTC 0-3 高峰);记录 p50/p90/p99/max。
- **口径警告:**demo 撮合后端性能 ≠ 生产;demo 数字只用于软件路径验证
  与相对比较,不得当生产延迟引用。
- 凭据:demo key 走 `~/.kalshi/env.sh` 同等纪律,不入库不入日志。

### Tier 3 — 测点对比:Mac vs 云端(零风险,与 Tier 2 同批做)
- 同一脚本分别从 Mac 和 us-east EC2(可复用 W09 或最小实例)打 demo。
- 预期:Mac 住宅网络 ~30ms RTT vs 同区域云机可能 ~1-5ms——如果确认,
  **生产执行机放云端**就是一条免费的 25ms,这个数字直接决定部署架构。

### Tier 4 — 生产环境微基准(有真单,默认锁死)
- 内容:流动性死角市场远离盘口挂 1 张 → 立即撤,测真实生产 ACK 延迟。
- **前置(GUARDRAILS 硬门):**全部生命周期关卡绿灯 + 操作员当次明确
  授权 + 单独风险预算(最大挂单张数/价位边界/总敞口上限写死)。
- 本计划**不含** Tier 4 授权;届时另行请示。

## 验收标准
- 每层产出:样本 ndjson + 汇总表(p50/p90/p99/max、分时段)+ 一图。
- 引擎签名耗时若 >1ms,自动登记优化债(预签名/会话密钥/并行化方案)。
- 结果写入 `docs/LATENCY_FACTS.md`(新建,数字带测点/环境/时间戳),
  作为后续所有策略延迟假设的唯一引用源(费用墙之外的第二面墙)。
- 全程无生产订单(Tier 4 除外且本计划未授权)。

## 一句话优先级
先知道自己多快(Tier 1),再知道路多长(Tier 2/3),最后才谈值不值得
搬家和加速。所有 backtest 里的延迟假设,从此引用实测,不许拍脑袋。
