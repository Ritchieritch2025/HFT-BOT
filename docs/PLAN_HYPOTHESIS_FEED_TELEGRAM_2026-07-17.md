# W-HYPO-FEED-01 — 假设→Telegram 实时推送 + 操作员回判

**Status: PROPOSED — 操作员需求(2026-07-17),待实现。**
**操作员原话(逐字):**"我需要每一个假设到实验的想法都变成一条描述推送到
我的 telegram 里面,这样我可以跟进 research 进度并且加入我自己的判断。"

## 目的

让操作员在**确认门之前**就介入判断:每冒出一个假设/待验想法,实时收到
一条描述,能当场表态"深挖 / 搁置 / 毙掉",而不是等最终报告才看到。
落在 deep03 的 `OPEN_DISCOVERY_UNIVERSE`(开放勘探)通道——推送的是
探索证据与提案,**不是**已裁决的策略。

## 数据源(复用,不另造)

- 研究端已有 `HYPOTHESIS_LEDGER.json`(每个假设一条记录)。
- 推送端已有 `deploy/tg_intel.py` / `tg_common.py`(Telegram 情报推送)。
- 本 W = 把两者接起来 + 一个操作员回判回路。**不新建推送框架。**

## 推送内容(每条假设一张卡,力求 30 秒可判)

每当 ledger 新增或状态变更一个假设,推一条:

```
🔬 新假设 <H-ID> · <运动/市场>
一句话: <这个假设赌的是什么规律>
机制猜想: <为什么可能成立 / 谁在付钱>
数据支持: <当前样本量 · 覆盖 · 是否够验>
状态: EXPLORATORY_ONLY(探索证据,未裁决)
下一步: <描述性扫描 / 提案进确认门 / 待数据>
你的判断? 回复: 深挖<ID> / 搁置<ID> / 毙<ID> / 备注<ID> <文字>
```

分级(沿用监控三色纪律,防刷屏):
- 🔬 新假设诞生、状态跃迁(探索→提案)= 推送;
- 例行的参数微调、同假设的重复扫描 = 不推,进当日汇总;
- 每日一条"假设进度汇总":新增 N 条、深挖中 M 条、你待判 K 条。

## 操作员回判回路(关键 —— 这是"加入我自己的判断"的落点)

- 你的回复(深挖/搁置/毙/备注)**写回 ledger** 对应假设的
  `operator_note` 字段,带时间戳与 approval-style ID。
- 回判**不等于**确认门授权:它只影响探索优先级(agent 据此排先后、
  弃搁置项),**不能**把一个假设直接推过 D0-D3 门。确认仍走既定严格通道。
- "毙"= 该假设进 `REJECTED_BY_OPERATOR`,附你的理由,不再自动重提
  (防僵尸复活)。

## 边界(防跑偏)

- 推送是**只读广播 + 优先级回判**,bot 不因你的回复执行任何研究计算、
  开支、开洞或晋级 —— 沿用"只报不控"铁律。
- 探索证据永远标 `EXPLORATORY_ONLY`,推送里不得出现"可交易/edge/
  已验证"字样(那是确认门之后的事)。
- 凭据/chat 白名单沿用现有 tg 机制,不新增暴露面。

## 验收

- 造一个测试假设写入 ledger → 30 秒内到操作员手机;
- 操作员回复"搁置<ID>" → ledger 对应字段更新、当日汇总反映;
- 重复扫描不刷屏(进汇总);连续 3 日汇总准点。

## 实现纪律

单独一个 W、复用现有 tg + ledger、五条刹车、独立审计、PLANS_LEDGER 登记。
不接入任何写 S3 / 下单 / 开支路径。
