# AGENT BRIEF — 交给 Agent 的单一入口文件

> **这就是要喂给 agent 的那份文件。** 它把其余四份串起来,定好规则,给出第一步。

## 使命
建一个 Kalshi 体育做市（market-making）bot。依据 = 5 篇已验证的论文(不是从零挖规律)。方法 = 自底向上、一次一个组件、每个单独测。关键定义由操作员拍板。

## 先读这四份（都在 `docs/`）
- **`BUILD_PLAN_LIT_TO_MODEL.md`** ← 路线图 + 决策门总表。**你按它执行。**
- **`AGENT_TASK_01_CALIBRATION_TEST.md`** ← 第一个具体任务(Phase 0+1)。
- `MM_DOCTRINE_FROM_LITERATURE.md` ← 结论与公式来源(参考,P/B/O/H/W 各条)。
- `TOOLS_TO_BUILD.md` ← 工具规格 T0–T15(参考)。

## 操作规则（硬约束）
1. 按 BUILD_PLAN 执行,从 **Phase 0 → Phase 1** 开始。
2. **每到决策门,停下,用"选项 + 推荐默认"问操作员**;不许自己猜关键定义。
3. **只读**现有已封存数据(7/10–17);不写生产、不碰实盘,直到 Phase 5。
4. **不做大数据挖掘**;策略来自论文,你的活是"实现 + 在我数据上验"。
5. 每个组件单独造、单独验;**GO/NO-GO 不过就停下报根因,不硬冲**。
6. 输出用**大白话**;样本不够就如实说"要更多天",不硬凑。
7. **不需要新的 AUTHORITY/ARM**——这是对现有数据的只读研究查询。

## 操作员已定的决定（默认 = 推荐值 ★;操作员可随时覆盖）
- **Phase 0**:数据源 = **S3 全部已封存数据(所有市场/系列,现有 8 天)——不预先只取网球**;时钟 = 收报。第一测试在全部数据上、按市场族切分,让数据排出哪个族的 edge 最肥(网球只是候选之一)。
- **Phase 1(D1–D5)**:见 AGENT_TASK_01,**全部按 ★ 推荐默认**。
- **Phase 2 及以后**的决策门:到那一步再停下问操作员。

## 现在就做（Phase 0 + Phase 1）
造 **T0(读数据:成交带 taker 方向 + 盘口 + 结算)** + **T4(校准)**,在网球 8 天数据上回答一个问题:

> **"在我全部已封存的市场里(按市场族切分),哪些族群众系统性地把 YES 买贵了(隐含 YES 价 > 真实结算率)?各自幅度多大、样本够不够?排个名,指出最肥、最可靠的战场。"**

**交付**:
- 先跑 **T1 市场分类**(单名 / 宽基 / 网球 / 其他体育 / 政治 / …),把全部市场归族。
- **每个族一条校准曲线**(隐含价 vs 真实结算率,10¢ 桶,等权+量权)+ 高估幅度(百分点)。
- **一张排名表**:族 → 中价高估幅度 → 样本量(结算了多少市场/多少笔)——诚实标注,样本小的族不许过度解读。
- 一句大白话结论:哪个族值得先做、哪个 edge 太薄/样本太小别碰。

**过/不过**:至少有一个族的中价 YES 高估明显 > 成本、且样本够 → 进 Phase 2(先做那个族);全都不够 → 停,如实报告"现有数据里没有足够肥的 YES 高估,要么换/加数据、要么换 edge",省下后面全部白工。
