---

读 docs/GUARDRAILS.md、docs/BACKLOG.md 的 timestamp-ladder 条目后,
执行 W-TL1(时间轴校准·第一步,本地 only)。范围与口径钉死如下:

1. schema:staging 三张表(orderbooks_l1/trades/orderbooks_full)
   additive nullable 加四列:exchange_ts_us、recv_wall_ns(raw
   envelope 原值)、recv_mono_ns(原值)、local_recv_ts_us
   (recv_wall_ns//1000)。未来新导出的 archive 分区自然携带四列;
   existing archive files are never rewritten;旧 archive 文件经
   union_by_name 读回 NULL——只保证新数据正确,不修旧数据。
   exchange_ts_us 归一化:ts_ms authoritative(毫秒×1000);
   ts 仅为 legacy fallback——数值按秒解析,字符串按 ISO-8601
   解析,其余 NULL。
   ts_utc 保留仅作 legacy 兼容:ts_utc = COALESCE(exchange_ts_us,
   local_recv_ts_us),仅用于旧工具兼容/分区/粗查询,不得作为
   tradable replay clock(代码注释写死)。

2. ingest:从 raw envelope 填四列;三张表的 INSERT 全部改为
   explicit column list(仿 orderbooks_full 的 FULL_INSERT 模式,
   杜绝列数变化导致的位置错位)。
   scheduled heartbeat 行(系统定时补的状态延续行,非交易所
   消息)写法钉死,两边都不许错:
     ts_utc = 整点时间(照旧!老 pipeline 的按日导出/LOCF/
       心跳识别依赖它,写 NULL = 破坏生产,验收 FAIL)
     exchange_ts_us / recv_wall_ns / recv_mono_ns /
       local_recv_ts_us = 全部 NULL(心跳没有真实消息,
       伪造时戳 = 污染时间轴,验收 FAIL)
   注释写明:heartbeat 可用于 LOCF 状态延续,不得作为"策略新
   看见市场变化"的触发事件;不进任何 lag/jitter/residual 统计,
   单列计数。

3. export/load:union_by_name 兼容旧文件(旧文件读回 NULL)。

4. mm_backtest:
   a) 显式决策钟,default clock=recv;clock=exchange 只允许作为
      诊断/验收对照,用途仅限证明 look-ahead bias,其结果不得
      用于 go/no-go。缺 recv 的行 fail-closed 并输出统计,仅
      --allow-missing-recv 显式放行,禁止静默回退 exchange time。
   b) 最小 active-quote 延迟模型(机制必须实现,否则第 5 条
      验收不成立):quote 在 book update 时生成;
      decision_ts_us = local_recv_ts_us + processing_chain_p99_us
                       + signing_p99_us
      order_effective_not_before_us = decision_ts_us
                       + signed_post_rtt_p99_us
      早于 active 时刻的成交不得 fill。
   c) 三个 p99 参数为 config 记录的保守占位值(默认值写死并注明
      PLACEHOLDER),真实测量(processing 全链 recv→入环→book
      apply→strategy seen→order intent;signing 单列,RSA-PSS
      本地基准;RTT 用 signed POST/全链同类请求 p99,禁用普通
      GET 均值)是独立后续任务,采样方案不碰真单、单独提交
      操作员过目。本 W 不测参数,只建机制。

5. 验收核心(演示,非描述):本地 fixture 构造"消息晚到"场景,
   证明 clock=exchange 回测产生假利润、clock=recv +
   active-not-before 不产生。

6. jitter 报告工具落 work/research/。
   数据源钉死:读 raw NDJSON envelope 或本地 fixture,不从
   warehouse 硬算——stream_epoch/连接边界信息只有 raw envelope
   里完整,warehouse 表没有;从 warehouse 计算 reconnect-aware
   residual = 验收 FAIL。
   口径:lag_us = local_recv_ts_us − exchange_ts_us,仅作诊断
   (observed lag proxy);负值唯一正确解释:交易所钟相对我方快,
   或我方钟慢。
   主指标:jitter_us = lag_p99 − lag_p50(按小时窗);
   pacing_residual_us = (recv_mono_ns[i]−recv_mono_ns[i−1])/1000
                        − (exchange_ts_us[i]−exchange_ts_us[i−1])
   residual 边界:按到达顺序;按 market_ticker/category/table
   分桶;跨 stream_epoch/reconnect 不差分;Δexchange_ts_us<0
   不进残差、单列乱序计数;批量特征(先正尖峰后一串负值)识别后
   单独标注。
   报告列(全列,缺一即验收 FAIL):capture_host、category、
   table、sample_count、lag_p50/p90/p99/min/max、jitter_us、
   residual_sample_count、residual_p50/p90/p99/min/max、
   missing_exchange_pct、missing_recv_pct、negative_lag_pct、
   exchange_out_of_order_count、heartbeat_count_excluded。
   capture_host 判定(禁止仅凭时间戳硬判):路径/来源元数据可
   证明 EC2 → EC2;割接前 → Mac/pre-cutover;重叠期无法证明
   host → unknown_overlap,排除出 go/no-go。仅 capture_host=EC2
   (2026-07-09T23:09:07Z 独占期起)可用于正式校准/latency/
   toxicity/shadow gate/go-no-go;其余仅开发/fixture/sanity。
   所有含 exchange_ts_us 的指标脚注强制携带:
   "Kalshi exchange timestamp is millisecond-granular. Sub-ms
   conclusions are not supported. Sub-1ms variation in the EC2
   era is primarily timestamp quantization / upstream batching
   behavior, not transport jitter."
   验收口径:W-TL1 report acceptance uses local synthetic/raw
   fixtures only。生产 EC2 报告在部署后生成,不属于本 W。

7. 新工具进 tools.json(safety class),docs/warehouse_schema.md
