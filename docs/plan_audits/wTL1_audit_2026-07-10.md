## Findings

**N1 — doc/code exit-code mismatch.** `tools/mm_backtest.py:26` docstring says fail-closed is "exit 1"; the code returns **3** (`tools/mm_backtest.py:261`), and tools.json/tests say 3. A script keying on the documented code would mis-handle. One-word fix.

**N2 — heartbeat predicate lacks hour-alignment guard (legacy silent-exchange-fallback hole, empirically vacuous).** `tools/mm_backtest.py:174-176` classifies heartbeats as `is_snapshot & price_e4 NULL & all-NULL ladder`. A pre-TL1 *first-observation* snapshot lacking `price_dollars` would match and be silently replayed at ts_utc (= exchange time) under `--clock recv`, bypassing fail-closed — a literal breach of §4a for that row class. I probed both real stores: **0** such non-hour-aligned rows in 47.2M staging + 50.3M archive rows, so not blocking. Adding `ts_utc % HOUR_US == 0` to the predicate closes it exactly.

**N3 — heartbeat replay can leak up to one arrival-lag of state.** A heartbeat at `h_start` carries book state from the last real tick before the boundary-crossing tick (`tools/ingest.py:346-355`). If that source tick was a late arrival straddling the hour boundary (exchange ts < h_start < recv ts), recv-clock replay shows its state at h_start — before we physically saw it. Bounded by that tick's lag (~ms vs the 67ms placeholder chain), and inherent to the spec-pinned `ts_utc = hour start` rule, but the caveat is documented nowhere. Should be written into mm_backtest/schema doc.

**N4 — fill eligibility is optimistic by one downlink lag.** `on_trade` compares the trade's *recv* time against `order_effective_not_before` (`tools/mm_backtest.py:116,121`). A trade that printed at the exchange up to lag_us *before* our order went live but arrived after it passes the check. Not look-ahead (never uses data pre-arrival), but it nudges the Q2 pessimistic bound optimistic by ~ms. Document, or use exchange print time for eligibility only (never for decisions).

**N5 — jitter_report emits junk empty buckets.** `work/research/jitter_report.py:174` creates the bucket before the `table is None or not mt` rejection at line 179-180, so unattributable records materialize `_other` rows with sample_count=0/all-None in the CSV (they are also correctly counted in `bad`). Cosmetic.

Verified: only `./work` exists, jitter_report.py tracked, all data under work/ still ignored, report CSVs ignored via `work/research/*`.
