## VERDICT: ACCEPT-WITH-FINDINGS

The four scenario tapes are **real demonstrations**, not green-that-can-lie: I traced every mutation named and each is caught. The day-loss tape genuinely wires the real `RiskLedger` layer-⑤. Build clean, 27/27 checks PASS, registry ok, forbidden files untouched. But I found **two real, untested defects in the engine dead-man** — one fail-OPEN, one spurious-mass-cancel — both confirmed by probe. Neither is a green-lie in the existing tape (the tests don't exercise these paths). Because both errors in the live path are ultimately backstopped (per-order TTL + exchange-side order-group dead-man), this is findings, not a reject — but B1/B2 must be fixed before this module is trusted as the standalone safety net.

### B1 (fail-OPEN) — engine dead-man requires a prior heartbeat to arm; an engine that never heartbeats never expires its resting orders
`rule_engine.hpp:118-120`: `engine_dead = window!=0 && hb_seen_ && now - last_hb > window`. The `hb_seen_` guard means a RestingOrder with the default `expiry_ns=0` ("engine dead-man only") has no expiry path until at least one heartbeat has ever arrived. Probe: add two resting orders, never call on_heartbeat, on_tick one hour later → expired=0, resting=2 (FAIL-OPEN). Backwards for a dead-man whose whole purpose is catching a dead engine; contradicts S6 ("every resting order carries expiry"). No test covers it. Fix: arm from the presence of resting orders (seed last_hb from first order time) or forbid expiry_ns==0.

### B2 (spurious mass-cancel) — unsigned underflow on an out-of-order/skewed tick expires and clears the ENTIRE book
`rule_engine.hpp:120`: `now_ns - last_hb_ns_` is unsigned; a tick with now < last_hb wraps to ~1.8e19 > window → engine_dead → all Expire + resting_.clear(). Probe: heartbeat at 1s, on_tick(1ns earlier) → expired=2 (spurious). The same author guarded this exact case in token_bucket.hpp:101 (`if (now_ns <= last_ns_) return;`) but did not carry it to rule_engine.hpp. Fail-safe-ish direction (over-cancel) but a 1ns glitch wiping the book + desyncing resting_ is a real defect, untested. Fix: guard `now_ns > last_hb_ns_` before the subtraction.
