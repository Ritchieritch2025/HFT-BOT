## FINDINGS

**N1 — CORRECTNESS (medium-high): the ack-loss scenario is mis-classified, and the remedy would tell the engine a LIVE order is terminal.** reconcile.py:130-139. Orders joined by `order_id` ONLY; `client_order_id` ignored even though account_view surfaces it (account_view.py:329). The failure reconcile exists to catch is a lost create-ack — the engine never learned the exchange order_id and keys by client_order_id. Probe: one physical resting order → BOTH ORDER_ONLY_IN_ENGINE (key CLIENT-abc) AND ORDER_ONLY_AT_EXCHANGE (key EXCH-REAL-123). The dangerous half: the ORDER_ONLY_IN_ENGINE remedy ("order is terminal; do not resend") issued for an order resting LIVE. Fix: join on client_order_id.

**N2 — D3/E4 BOUNDARY (medium): counts coerced with int(), silently accepting floats/bools → a green that lies.** reconcile.py:95,109. Probe: engine remaining 20000.9 vs exchange 20000 → CLEAN; True vs 1 → CLEAN. account_view rejects floats (parse_e4/e6). Reject at index time.

**N3 — COVERAGE (low-medium): price drift undetectable.** ORDER_ATTR_DRIFT compares only remaining + book_side. Probe: same id/remaining/side, price 0.40 vs 0.99 → CLEAN. Real-world risk low (a resting id is price-bound on Kalshi) but unstated + untested.

**N4 — ALARM DELIVERY (medium): the alarm is a log append no component delivers.** dashboard_server.py has zero alerts.log references; alert_notify.sh writes but never reads it; nothing forwards reconcile: lines. Delivery rides on exit code 1; alarm() swallows OSError. Tolerable for a manual tool but the RESULT overstated the notification path.

**N5 — TEST ROBUSTNESS (low): the no-resend gate greps only literal resend/retry.** "re-send"/"replace"/"reissue"/"re-transmit"/"re-submit" would pass.

**N6 — S2 SOFTNESS (low-medium): POSITION_DRIFT says "consider panic if large" with no threshold/escalation.** A 1-unit and a catastrophic delta get identical advisory text. A large signed delta arguably warrants a hard panic recommend.

**N7 — REGISTRY SAFETY CLASS (low): reconcile declared offline but --live does a live account read.** Understates privilege vs account_view/panic_dryrun (network_read). A console arming only offline-class could trigger a live read via --live.

Coverage gaps: no test for order_id/client_order_id ambiguity (N1), price drift (N3), float/bool coercion (N2), or abs-vs-signed position (opposite-sign same-magnitude).
