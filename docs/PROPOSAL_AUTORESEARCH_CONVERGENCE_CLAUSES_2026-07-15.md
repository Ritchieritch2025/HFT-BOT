# PROPOSAL — Autoresearch 收敛条款(五条刹车)

**Status: PROPOSED — 待操作员裁决,未生效。**
**Origin:** 2026-07-15 deep01 运行复盘。操作员裁定的核心问题:"如果没有叫停,
自我修复循环会一直反复下去,迟迟看不到结果。" 收敛条件当日仅存在于操作员
脑中,未写入任务书 —— 本提案将其制度化。
**Proposed by:** operator 陪跑 session(Claude),2026-07-15。
**Evidence base:** deep01 实际耗时 —— 真实计算 <1h;数据缺陷返工 ~2h;
工具建设与自我加固(含 repair-03/04/05 递归)占大半天。两次由操作员人工
干预才收敛(优先级裁决 + 范围收紧令)。

采纳后应合入:autoresearch 任务书模板(PLAN_SPORTS_TRADING_PROGRAM_PROMPT
后续版本)。逐字条款如下。

---

## 条款一:时间盒(Time Box)

每类工作预设时间预算。默认值(任务书可改,不可删):

- 数据修复/工具加固类工作:单次连续投入 ≤ 45 分钟。
- 超时的唯一合法动作:**停下,向操作员报告**(已完成什么、为何超时、
  续批申请),等待裁决。沉默续干 = 违规。

## 条款二:递归上限(Recursion Cap)

- 裁定:登记器/终审器/收据工具**自身**的代码缺陷属工程债,不属于
  "数据修复",不触发新的 repair 注册。"修复须注册"条款只约束
  (a) 数据处置 (b) 研究计算代码。
- 每次运行的数据修复注册次数上限 = 3。达到上限后再遇到需修复事项:
  任务中止,整体移交操作员,不得自行开 repair-04。
- (本条直接来源:deep01 的 repair-04/05 为登记器修登记器的递归,
  操作员终止后才收敛。)

## 条款三:完成的定义(Definition of Done)

- 每道关卡在**开工前**写死合格线。默认:专项测试全绿 + 交叉审计
  0 Critical / 0 High。
- 低于该线的审计发现(Medium 及以下、纯理论场景)一律登记为工程债,
  **不阻塞**当前运行。
- 审计的职责是分级,不是清零。"还能更严格"永远为真,不构成阻塞理由。

## 条款四:心跳契约(Heartbeat)

- 超过 20 分钟无新落盘产出(文件/提交/状态更新),必须主动发出状态
  报告:当前在做什么、卡在哪、预计还要多久。
- 子任务("Waiting for agents")空转视同无产出,计入 20 分钟。

## 条款五:并行许可(Parallelism Grant)

- 任务书显式列出允许并行的步骤对(例:数据扫描 ∥ 工具加固;
  终审器只需在"打开结果"前完工,不阻塞扫描点火)。
- 未列明的默认串行;已列明的不得自作主张改为串行等待。
