## 1. 他们的 edge 是什么(按重要性排序)

**E1. 外部成熟市场做 fair value 锚("top down")。**
他的公允价不是自己建模,而是抓 Pinnacle 等 sharp sportsbook 的赔率
(L1279, L1949)。原话:体育在别处已是超成熟市场(L2005)。
→ 这正是我们 crypto 板块的结构:BTC/ETH 现货指数领先 Kalshi 盘口
(MM_ROADMAP 阶段 1.5A)。**edge 的本质 = 有一个比 Kalshi 更快更准的
参照物**,他的参照物是 Pinnacle,我们的是现货。

**E2. 爬虫速度。**
"别指望用任何(慢的)API,必须爬得非常快"(L1285-1287)。他的竞争
就是谁先看到 sportsbook 移动。→ 对我们:等价物是现货行情延迟,
这是 AWS 迁移(MASTER_SEQUENCE STEP 1)的价值所在。

**E3. Kalshi 费率结构本身是 maker 的护城河。**
taker 费 ~7%,maker 0 费:"我要错得离谱得多才会被占便宜,
相比零费率平台"(L2035-2041)。sharp 想吃你的价,先要跨过费用墙。
→ 我们 GUARDRAILS 里"费用进每个模型"是对的,而且方向对我们有利:
悲观口径下对手的成本要按 taker 费算。

**E4. RFQ/combo(组合请价)市场:高毛利 × 低竞争 × 散户爱玩。**
"super high margin + 很难做 + 别人做不了"(L1480-1493)。
RFQ 流里只有 ~0.1-1% 是"知情/负 EV"单(L1873-1875, L2647),
其余全是 rec flow(散户流)。Kalshi 只开三个主流球员市场,
没有 FanDuel 那种长尾深度,散户很难找到真正错的价(L1879-1887)。

**E5. 对手方识别与拉黑。**
Kalshi 在 RFQ 里带一个跨天固定的 requester ID(L1683-1695)。
他用历史成交回查谁在赢他,然后"不再报价给你"(L1699-1706)。
行为过滤:同一账户几秒内连发多单 = 机器人,人类做不到(L1607-1613)。
→ 他自己也承认多账户绕过很容易:借别人 KYC 账户的 API key 即可
(L1823-1827),所以拉黑是弱防线,不能当主风控。

**E6. 与交易所利益对齐。**
"我的利益和 Kalshi 高度相关"(L2095):maker 给交易所创造的费收入
比自己赚的还多(L2075-2079),所以平台愿意保护你;taker/sharp
随时可能被"产品决策"清出去。→ 战略层结论:做 maker 是
监管/平台风险下相对更稳的位置,和我们选 MM 路线一致。

**E7. 专注。**
"把一件事做到很好,比把一堆事做到及格容易"(L2845-2849)。
只做 Kalshi、只做体育,不碰 Polymarket(学习曲线不值,L2015-2023)。

## 2. 可借鉴的策略(我们计划里还没有或没写透的)

**B1. 报价规模的"一口闷测试"(sizing heuristic)。**
他定挂单大小的唯一准绳:"如果有人一次点掉我整个挂单,我作何感受?"
(L1025-1037)。高尔夫场上被一口吃 $20k = 坏;Lions moneyline
被吃 $50k = 开心。→ 可形式化为:**挂单量 = f(该市场毒性分布)**,
即 tox_120s_lo 越差的市场挂越小。写进阶段 1.5B 的报价生成:
δ(半径)和 size(规模)都要吃毒性输入,目前计划里只有 δ 吃。

**B2. 队列位置 vs 挂单规模的权衡要显式建模。**
挂大单 → 被快枪手打的敞口大;挂小单 → 别人在你后面压大单,
你的队列优先级失效,"一小时都轮不到你成交"(L975-1005)。
→ 我们的 λ(δ) 标定(阶段 1.5C)目前只测"距 touch 距离 vs 成交强度",
应加一维:**同价位队列深度对成交概率的影响**(L1 数据里有 qty,可标定)。

**B3. 心跳监控(dead-man switch)。**
每个 bot 每分钟 ping 一个外部网站,断 ping → 网站反向推送告警
(L1217-1239)。→ 我们管道有 launchd 自愈,但**策略引擎**
(阶段 2 shadow 起)应加同样的外部心跳,写进阶段 3 安全门清单。
成本半天,价值:他两次大亏都是"看通知才发现"。

**B4. 大额成交异常告警(不是全量通知)。**
他靠手机全量推送人肉发现了 hockey 价格翻转 bug(L1143-1148),
自己也说正确做法是"只推 >$500 的成交"(L1155-1160)。
→ 我们 dashboard/metrics 已在建:加一条**单笔成交 > X 阈值 →
操作员通知**,微实盘(阶段 4)前必须有。

**B5. 对手方毒性分层(远期)。**
CLOB 上看不到对手 ID,但 RFQ 有(E5)。若将来做 RFQ:
维护 requester ID 的历史盈亏表,毒性高者不报价或加宽。
另一个方向他提了没做:被同一 sharp 反复打后,**跟着 sharp 的单
反向去别处下注**(L1843-1861)——本质是把被动的逆向选择
变成信号。记入 BACKLOG,非当前阶段。

## 3. 必须注意的陷阱(他真金白银亏出来的)

**T1. 最大且持续的亏损源 = 比你快的信息流(courtsider/快 feed)。**
NBA 每晚被同一伙人(5 个账户同毫秒同单,L1545-1553)在他看到
sportsbook 移动前打进来;高尔夫上线第一天被"刚打到旗杆两寸"的
courtsider 吃 $20k(L697-709)。**"Kalshi 先动"= 你的参照物已经旧了**
(L527-535, L1289-1291)。
→ 我们的对应物:当 Kalshi 盘口先于现货指数移动,说明有人有更快的
现货 feed 或知情流。阶段 1.5B(c) 的**报价速度熔断正是解药**,
本访谈是它必要性的又一实证。注意他的教训补充了一点:
熔断之外,**新市场/新品类上线第一天用最小 size 试毒**
(他高尔夫第一天就满额挨打)。

**T2. 亏损大头是工程 bug,不是模型错。**
他历史最大单日亏损全部来自代码错误:
(a) hockey spread 正负号爬反,被人连扫(L765-783);
(b) 单笔限额只按"一条线"算,10 条相关的 alternate line 同时被打,
    $5k 限额实际敞口 $50k(L613-639);
(c) parlay 风控把相关腿当独立腿,被人用"同一强相关腿 × 每个 NHL
    moneyline"套模板打(L803-815)。
→ 直接映射到我们 GUARDRAILS:边界校验、E4 定点数、测试同变更。
具体要加的硬检查(阶段 3 风控闸):
  - **按 event 聚合的净敞口上限**(不是按 market)——bracket 内
    各腿相关,等价于他的 alt-lines 坑;
  - **fair 与外部锚的偏离夹钳**:自算 fair 偏离现货推算值超阈值
    → 拒绝报价(防正负号/单位类 bug 直接上盘)。

**T3. 没有外部领先参照的市场不要做。**
天气类市场若用自家盘口 mid 当 fair,别人 $500 就能推动参照价
再反手打你(L1943-1963);"天气没有 Pinnacle"(L2005)。
→ 写死为 mm_scan 的准入规则:**候选市场必须有可验证的外部锚**。
crypto ✅(现货指数);mentions/politics/天气 ❌(现阶段禁做)。

**T4. RFQ 生态里 sharp 用请价当免费扫描器。**
有人每秒发上百个 RFQ 纯粹找错价,而 maker 响应上限 ~30 个/秒
(L1636-1663)——你的响应预算被 sharp 挤占。→ 若将来做 RFQ,
响应配额本身是稀缺资源,需要按 requester 毒性分配。
(我们 CLOB 写配额 300/s + token 桶已覆盖当前阶段。)

**T5. 平台/监管尾部风险,收入不可外推。**
他自己说:换 CFTC 主席或最高法院一纸判决,Kalshi 体育可能整体消失
(L2249-2253, L3028-3047);"别把这个月×12 当年收入"(L2471-2483)。
→ 对我们:crypto 类比体育的监管暴露低,但同样不可假设永续;
这是"最小可亏损金额起步、每阶段有退出条件"路线的又一佐证。

**T6. 结算规则文本要全文读。**
他在 Super Bowl 表演市场只看了半条规则("必须上麦克风"),
漏了"跳舞也算",85¢ 买入亏 ~10%(L1345-1353)。
→ 我们已有 PLAN_TOKEN_RULES / 规则解析方向;微实盘选市场时
规则全文进 checklist,不能只读标题。
