# 工单:做市执行层 —— 策略绑定 + 速度军备 双线 v1 · 2026-07-21

**决策人要求**:选对市场(策略)和抢得够快(速度)两条腿都要。
**本工单原则**:两线并行规划,但按"真金风险递增"分阶段落地。每阶段可测可回退。
纯软件先行,真单代码最后且逐步。审计按每阶段"验收门"核。

## 双线结构

### 线 S(策略绑定)——决定"在哪、以什么价做市"
做市不进红海拼微秒,只在我们研究清楚的市场做:
- **选市场**:只在"信息落地/散户上头"分析判定安全的 single-name 市场做市;
  用 universe_classes 开关 + 逆向选择曲面(deep03 产出后)选战场。
- **报价**:校准底线报价(BO-2)——按真实概率+毛利+库存偏移定价,不是跟市价。
- **撤退**:VPIN 撤退线 + 信息落地流识别器(EDGE 立项)报警即撤/让。
- 产出:一个"该挂/撤哪些单"的决策函数,可回放测盈亏。

### 线 V(速度军备)——决定"能不能抢到那个位置"
- **测**:先量清楚"从看到盘口变化 → 我们的单到交易所"的全链路延迟 p99。
- **优**:热路径无锁、预签名、连接常驻、决策微秒级(部分已有)。
- **抢**:队列位置模型——挂在盘口顶才收得到流;被超越就重挂。
- 现实认知:我们速度未必赢专业 bot,优势在选市场(线S),速度是"够用不掉队"不是"最快"。

## 分阶段落地(风险递增,每阶段一个验收门)

### 阶段 1 · 影子做市引擎(纯软件,零真金)
建挂单登记表 + 订单状态机 + 仓位账本,**纯内存 + 影子模式**:接真实 WS 盘口,
做出做市决策,只记录不发送。
- **可测**:回放 tape 验状态机正确性;历史盘口上看做市决策盈不盈利。
- **验收门**:回放确定性(同盘口→同决策→同影子P&L);状态机单测全过;
  影子做市在回放里的点差捕获 > 0(扣费悲观口径)。
- **我能自己搭大部分。** 对接线S的决策函数 + 线V的延迟标注。

### 阶段 2 · 单笔真单闭环(demo 环境,风险出现)
接真实下单/撤单/成交回读,demo 环境跑"一个市场、一手单"完整闭环:
挂→成交/撤→对账。动 `gateway.cpp:174` 的 Live 臂(现在 throw)。
- **验收门**:demo 上挂-撤-成交-对账链路无丢单、无幽灵单、断线能自动对账;
  client_order_id 幂等;F9 歧义失败矩阵正确 reconcile。
- **真单代码,每步要决策人确认。** 这就是 WO-B(风控闸)+WO-C(订单机)的合并落地。

### 阶段 3 · 小额生产 + 队列位置(真金,最小额)
demo 闭环稳后,生产环境最小额(单市场几十美元)跑影子验证过的策略。
加队列位置模型 + 速度优化(线V)。
- **验收门**:生产小额实盘 P&L 与影子/回放对得上(±可解释误差);
  kill switch 可靠;单市场/日/总敞口硬帽生效。

### 阶段 4 · 抢盘口(速度成为瓶颈才做)
前三阶段速度都不是瓶颈(信息落地是分钟级)。只有确认"点差捕获受制于队列位置"
才投入微秒级军备。

## 硬约束(贯穿全程,审计必核)

- **真单默认关**:任何真单能力有独立开关,默认 off,demo→小额→放大逐级人工确认。
- **风控前置**:RiskGate(WO-B)在 submit 之前,单市场/日/总敞口硬帽 + kill 文件。
- **maker-only**:做市只挂单不吃单(吃单交 taker 费,破坏点差经济)。
- **影子/真单分账**:client_order_id 前缀区分,永不混。
- **回放优先**:任何策略上真金前必须过回放 + 样本外验证(见 EDGE 立项铁律)。
