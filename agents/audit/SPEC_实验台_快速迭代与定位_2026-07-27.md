# 实验台规格:快速迭代 / 可回滚 / 可定位

> Audit(Cowork Claude)· 2026-07-27
> 目标(操作员原话):**找到最适用的参数和机制,快速实验迭代,每一步保留数据方便回滚,并 pinpoint 问题。**

---

## 0 · 核心洞察:三个目标是同一个前提

**快、可回滚、可定位——三件事都只依赖一个东西:确定性重放。**

```
(State 流, params, code SHA)  →  完全相同的决策序列(逐位)
```

有了它:

- **快** = 扫参就是把同一条 State 流重放 N 遍,**不碰交易所、不碰网络,可并行;**
- **可回滚** = 参数是数据不是代码,回滚 = 换一个指针;
- **可定位** = 两次运行结果不同 ⟹ **二分到第一个分歧的决策,并报出是哪个输入字段变了。**

**没有确定性,三个都做不到,而且做不到的方式是隐蔽的**(今晚"影子 5494 / 实盘 0"就是两条路径不确定的代价)。

**确定性由 `core/` 纯函数 + State 单一契约提供。本规格是它上面的那一层。**

---

## 1 · Run:一切产出的最小单位

**任何一次回放、扫参、影子、实盘,都是一个 Run,产出一个不可变目录。**

```
runs/<run_id>/
  manifest.json        ← 见下,内容寻址
  decisions.parquet    ← 每次评估一行
  fills.parquet
  metrics.json         ← 六指标 + 本 Run 的判据读数
  stdout.log
```

```json
{
  "run_id": "r_20260728_0913_a3f1",
  "kind": "replay | sweep_arm | shadow | live",
  "code_sha": "5dcc433e...",
  "params_sha": "9b2e...",
  "params_parent_sha": "7c11...",       // 父版本,用于"只改一项"检查
  "params_diff": ["k_uncert: 1.0 -> 1.5"],  // 必须列全
  "state_stream_id": "s_20260721_kxbtc15m",  // 输入数据的内容哈希
  "data_window": ["2026-07-21T00:00Z", "2026-07-22T00:00Z"],
  "window_class": "TRAIN | VALIDATE | OOS",
  "seed": 12345,
  "search_budget_seq": 47                // 全局第几次尝试
}
```

**规矩:**

- **`run_id` 一经产出永不修改、永不删除;**
- **报告里的任何一个数字必须能追到 `run_id`;做不到的数字不许引用;**
- `params_diff` **长度 > 1 的 Run,自动标 `MULTI_CHANGE`,不得进入归因比较**(一次一改,机器强制,不靠自觉)。

---

## 2 · State 流:存一次,所有臂共用 ⭐

**扫参的 N 个臂看到的是同一个世界。所以 State 流按市场窗口存一次,内容寻址;每个 Run 只存"引用 + 自己的输出"。**

```
state_streams/<stream_id>/  ← 只读,共享
runs/<run_id>/decisions.parquet:
    state_ref, t_ns, fair, fair_sd, as_value, as_sd,
    half_spread, skew, quote_bid, quote_ask, block_reason, params_sha
```

**两个好处:**

1. **存储成本从 O(臂数 × 时长) 降到 O(时长) + O(臂数 × 决策数);**
2. **成对比较天生成立**——所有臂在同一时刻看到同一个世界,**差分即效应,共同的行情方差全部消掉。这是小样本下能分辨小效应的唯一途径。**

**记录纪律:记输入,不只记输出。** 只记决策不记 State = 无法重放 = 无法定位。**今晚所有"为什么它当时那么判"的问题,都是这条缺失造成的。**

## 3 · 差分定位器(pinpoint 的具体工具)⭐

```
python -m tools.lab.diff RUN_A RUN_B
```

**输出必须包含:**

```
第一处分歧:  t=2026-07-21T14:23:07.412Z  market=KXBTC15M-...
  输入差异:   sigma_slow  0.412 → 0.418        ← 唯一不同的输入字段
  中间量:     as_value    0.83  → 0.91
              half_spread 1.21  → 1.29
  输出:       QUOTE(49) → BLOCK(SPREAD_INSUFFICIENT)
  此后分歧:   1,204 次决策(其中首次成交分歧在 t+38s)
```

**这就是"pinpoint":不是看总账变差了多少,而是看第一颗多米诺骨牌。**

**配套二分**:`tools.lab.bisect --params A --params B` —— 在两组参数之间逐字段二分,**找出到底哪一项造成了差异。** 参数多的时候,这比人读日志快一个量级。

## 4 · 扫参 harness(快的那部分)

```
python -m tools.lab.sweep \
    --stream s_20260721_kxbtc15m \
    --base params/v12.json \
    --grid grid_k_uncert.yaml \
    --window-class TRAIN
```

**硬约束(防止扫参变成过拟合机器):**

1. **网格必须粗**:单次扫参 ≤ 9 个臂;想要 30×30 → 先说明机制故事,再申请;
2. **每个臂必须只改一项**(`params_diff` 长度 = 1),否则拒绝启动;
3. **只允许 `window_class=TRAIN` 的流**;指向 VALIDATE/OOS 的流**直接拒绝运行**(不是警告,是拒绝);
4. **每次 sweep 自动 +1 全局 `search_budget_seq`,写入台账。**

**输出统一为成对差分表:**

```
臂        Δ净¢/笔    Δ成交/小时   Δ¢/小时    有效窗口数   95%CI(配对bootstrap)
k=1.0     基准
k=1.5     +0.04      −3.1         −0.02      412          [−0.09, +0.05]
```

**三个指标永远并排,任何一个都不许单独排序。**

## 5 · 搜索预算台账(过拟合按尝试次数计价)

```
lab/search_budget.jsonl
{"seq": 47, "date": "...", "target": "k_uncert", "arms": 5,
 "mechanism_story": "不确定度加宽应降低薄格成交毒性",
 "window": "TRAIN 07-21..07-25", "outcome": "无显著差异"}
```

**规矩:**

- **进扫参之前必须先写 `mechanism_story`**——"为什么物理上应该有效"。**写不出机制的想法不许进网格**(「锚动了报价旧」是机制,「周二效应」不是);
- **晋升阈值随 `seq` 收紧**(多重比较预算);
- **隐性尝试也算**:每天盯着面板心里否决掉的想法同样消耗预算 → **所以评审窗口必须预先定长,不到期不看结论。**

## 6 · 回滚语义:参数是数据,代码是代码,永不混

| 回滚什么 | 怎么做 | 秒级? |
|---|---|---|
| **参数** | `params/current` 指针指回旧 artifact SHA | ✅ 一条命令 |
| **代码** | git revert + 重新部署 | ❌ 分钟级 |
| **数据** | Run 目录不可变,天然无需回滚 | ✅ |

**推论:凡是可能需要快速回退的东西,必须做成参数而不是代码分支。**
**今晚那些 `MM_*` 环境变量既不是参数(无版本无哈希)也不是代码(不在 git 语义里),所以两种回滚都做不了——"本地修了 EC2 没修"就是这个空隙。**

**实盘额外一条**:实盘 Run 的 `params_sha` **必须出现在每条心跳收据里**。收据里的哈希与预期不符 → **自动 HALT**,不等人发现。

## 7 · 晋升流水线(和实验台的接口)

```
sweep(TRAIN, 可无限次)
   → 选出候选 params
   → shadow(前向,真 OOS,预注册窗口与判据)
   → 小信封实盘
   → 晋升: params/current 指针前移,旧 SHA 永久保留
   → 反向预注册: 跌破线自动指针回退
```

**铁律**:**同一段数据 + 同一个参数,最多调一次。** 再调必须等新交易日。
**理由**:调过之后那段数据对这个参数就"脏了",再用它评估就是自评。

## 7.5 · 零件化:每个函数都是可替换、可消融、可单测的部件 ⭐

**目标(操作员):像调机器学习模型一样,每个零件都能单独隔离、替换、测试。**

### 7.5.1 每个零件都有一个"空版本"

```python
class AdverseModel(Protocol):
    def __call__(self, s: State) -> Est: ...

class ZeroAdverse:       # 消融版:恒返回 Est(0.0, 0.0)
class PriorOnlyAdverse:  # 只用大盘先验,不用自家样本
class FittedAdverse:     # 完整版
```

**关键:消融 = 换一个实现,写在 params 里,不是改代码、不是加 if。**

```json
"components": {
  "adverse":   "adverse.fitted",
  "skew":      "skew.avellaneda",
  "shield":    "shield.zero",        // ← 这一行就是一次消融
  "exit":      "exit.age_ramp"
}
```

**后果:留一消融(ATTR-01 的 T4)从一个专项工程,变成一条随时可跑的命令。**

### 7.5.2 禁止散落的开关

**热路径里任何 `if MM_XXX_ENABLED` 都是零件化的敌人**——它让部件无法被隔离,也让消融必须改代码。
**所有变体走组件注册表,一个都不许留在函数体内。**
CI 检查:`core/` 中 `os.environ` 出现次数 == 0(已在 §1 纯度检查内)。

### 7.5.3 每个零件自带参数面(扫参可自动生成)

```python
@component("adverse.fitted")
class FittedAdverse:
    params_schema = {
        "k_uncert":        Float(0.5, 3.0,  story="不确定度加宽应降低薄格毒性"),
        "halflife_fills":  Int(50, 2000,    story="毒性记忆长度"),
    }
```

- **`story` 字段是强制的**(§5 的 mechanism_story 落到零件级);
- 扫参 harness 直接读 schema 生成网格,**不用手写 yaml,也不会漏项**;
- 搜索预算**按零件分账**——哪个零件被调得最多,一眼看到。

### 7.5.4 单件测试三件套(每个零件都要有)

1. **known-answer**:构造输入,断言精确输出;
2. **单调性/性质**:as↑⟹half_spread↑;σ_slow↑⟹上限**不**放宽;q↑⟹中心下压;
3. **空版本契约**:`ZeroAdverse` 接入后,全链路输出必须与"完全不含该项"逐位一致。

**第 3 条最容易被忽略,但它是消融可信的前提**——空版本如果不是真的空,所有消融结论都是错的。

### 7.5.5 ⚠️ 与机器学习的关键不同(必须写在消融报告里)

ML 里损失函数对固定数据集可算;**这里的"损失"是 PnL,而 PnL 依赖环境对我们的反应——换一套报价,成交集合就变了。**
**所以这不是监督学习,更接近离策略评估(off-policy evaluation)。**

**推论:零件分两类,消融的可信度完全不同。**

| 类别 | 零件 | 重放消融的性质 |
|---|---|---|
| **A · 不改变报价** | fair、鞅检验、四段账、markout、记录层 | **精确**。同一批成交,换个算法重算,结论可直接采信 |
| **B · 改变报价** | as_estimate、half_spread、闸、skew、exit | **仅与成交模型同等可信**。换了报价,历史成交集合本就不该一样 |

**硬要求:每份消融报告必须给结论打标 `EXACT` 或 `FILL_MODEL_DEPENDENT`。**
**B 类结论在影子成交模型完成实盘校准(命中率 ≥80%)之前,一律只作候选,不得晋升。**

### 7.5.6 一条反向提醒

ML 里加大搜索一般有好处(有 held-out、数据多)。**这里数据稀缺且非平稳,每次调参都在烧多重比较预算。**
**零件化的目的是"理解与消融",不是"把参数面做大好搜索"。**
**参数少而有机制故事 > 参数多而可调。** 新增一个参数前先问:**它能不能由数据自己定(EB 收缩那样),而不是由人来搜?**

## 8 · 验收(实验台本身怎么算建好)

1. **确定性**:同一 `(stream, params, code_sha)` 跑两遍,`decisions.parquet` **逐位相同**;
2. **三路一致**:replay / shadow / live 对同一 State 产出相同 Quote(实盘用录制回放验证);
3. **定位器**:人为改动一个参数字段,`diff` 能准确报出第一处分歧的时间、字段、中间量;
4. **拒绝多改**:构造 `params_diff` 长度 2 的 Run,harness **拒绝启动**;
5. **拒绝越窗**:把 OOS 流喂给 sweep,**拒绝启动**;
6. **回滚**:一条命令把 `params/current` 指回上一版,下一次心跳收据的 `params_sha` 随之改变;
7. **溯源**:随机抽报告里 5 个数字,**5/5 能追到 run_id → params_sha → code_sha → data_window。**

**七条全绿之前,不要开始大规模扫参——否则跑出来的结论没有一条能复现。**
