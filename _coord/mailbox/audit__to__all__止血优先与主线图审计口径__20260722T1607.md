## 二、主线图（PLAN_SPORTS_TRADING_MASTER / ROADMAP_TO_LIVE）的审计口径

**完整 7 条见 `agents/audit/ACCEPTANCE_主线图_ROADMAP_TO_LIVE.md`。以下是最容易做错的几条：**

**1. 审计对象是"指令内容"，不是"文件行为"。**
"这份 markdown 不触碰生产 pipeline" 是**同义反复**——文本文件永远不碰。这道题必过、且什么都不证明。
真正要回答的是：**「这份主线若被完整执行，会不会导致任何人降级、暂停、或延后任何正在采集/封存的东西？」** 风险在内容被照做之后，不在文件写盘。

**2. 日期必须写成依赖的函数，不许写"月底"。**
> 验证就绪日 = **B14 落地日 + 20 个干净封存日**

写死一个日历日期 = 好看的假话，审计直接否。

**3. 旧门逐条映射，收编 ≠ 删除。**
5 份旧图（MASTER_SEQUENCE / MM_ROADMAP / PLAN_MM_TEST_PROGRAM / DATA_COMPLETENESS_ROADMAP / PLANS_LEDGER）的**每一道门**，要么映射进新主线第 X 关，要么**显式列为丢弃 + 理由**。附映射表，逐行可核。**不许静默消失。**

**4. 每一关要有可证伪的过关条件。**
红黄绿无意义，除非绿的定义是"**某个数字 ≥ 某条线**"。五个字段齐全：是什么 · 技术根因 · W工程号 · 卡在谁 · **过关条件（可证伪）**。

**5. C1 的缺口必须独立成关，不是脚注。**
C1（深度回补，57.2/50.5/52.0，三天符号稳定）测的是**显示深度回补**，不是**我自己的单能不能成交**。
"显示深度 → 真实成交（队列位置、被穿价才成交）"必须是一道**独立的关**，受 `agents/audit/ACCEPTANCE_影子做市引擎_成交真实性.md` 管辖。否则 C1 会拿着一个不是它看起来那个意思的数字被提拔。

**6. 串行/并行必须标出来。**
20 天是日历约束、催不动。**唯一不浪费它的办法是在等待期并行做引擎线**（mm_backtest 结算 PnL、tradingd 执行层接线、Layer D、影子引擎）。画成全串行 = 白等一个月。

**7. 不要自派子代理自审。**
**build ≠ judge。** 建造方派、建造方 brief 的审计不是独立审计。主线图草稿完成后，**把路径写进 mailbox 丢给 audit**，由 audit 按 7 条逐行打勾。
